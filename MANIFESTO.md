# The Clinical UI Manifesto

Healthcare software does not need more visual sameness disguised as innovation.

It needs interfaces that know what job they are doing.

We believe:

1. **The work object comes before the dashboard.** A patient list is not a prelude to analytics; often it is the product.
2. **Context is a safety feature.** Patient, encounter, location, time and action scope must survive visual polish.
3. **Unknown is not no. Pending is not negative. Historical is not current.** State integrity is visual integrity.
4. **Density is not a defect.** Professional scanning tasks can require dense, aligned, comparison-friendly interfaces.
5. **Patients are not clinicians with fewer permissions.** Patient-facing software needs a different information model.
6. **Color is support, not semantics by itself.** Meaning must survive color-vision differences and degraded conditions.
7. **Charts must answer questions.** A donut chart is not a default state for percentages.
8. **AI does not deserve a sparkle icon.** Generated content needs scope, provenance, uncertainty and control more than visual magic.
9. **Accessibility is part of task performance.** It is not a final polish pass.
10. **Anti-slop is not anti-beauty.** It is anti-unexamined-default.
11. **Novelty is not the goal.** A conventional table can be excellent design when comparison is the task.
12. **Rendered behavior beats design intent.** Build, render, inspect, audit, revise.

The standard is not “does this look AI-generated?”

The standard is:

> Does this interface help the intended person understand the right thing and perform the right action with minimal ambiguity?

Then make it beautiful.
